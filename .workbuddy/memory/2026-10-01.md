**v2.9（第二轮，用户修订）**：起播点收窄为**点击第一幕 START 之后**（第一幕点击前全程静音），结束点不变。

### 素材实测（`wave` 模块直读 WAV 头，零依赖）
- **30.000 s**（`nframes 1323008 / framerate 44100`）
- PCM 16bit / 44.1 kHz / **立体声 2ch**（未压缩）
- **5,292,110 字节 ≈ 5.05 MB**，参考码率 1411 kbps
- ⚠️ **比第三幕视频（4.54 MB）还大** —— 所以不能塞进开场预加载（会毁掉「秒开」）→ Q30

### 关键判断：v2.9 的改法顺手消掉了一个技术前提
v2.8 要求「第一幕第一帧就播」，但浏览器禁止**无用户手势**的发声播放，而 Demo 是双击 `file://` 打开、那时玩家一次都没点过 → `play()` 必被 `NotAllowedError` 拒绝，我当时提了 **Q31**（「尝试 + 首次手势补播」双路径方案）。
v2.9 改成「点击 START 之后」后，**起播本身挂在真实用户手势上，限制天然不成立** —— Q31 直接取消，实现上不需要任何探测/兜底/补播。这是本轮最有价值的结论。
（对比：第三幕视频能自动播，靠的是「走到那里玩家已点过 4 次以上」，同一个道理。）
