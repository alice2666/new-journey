### O1–O3 已确认（需求 v1.3 / 计划 v1.1）

- **O1**：窗口小于 1200×896 时**整幅等比缩放**居中；≥1200×896 时 1:1 不放大。实现：`#viewport`(fixed inset:0, flex 居中) + `#stage` `transform:scale(min(w/1200,h/896))`，内部坐标完全不变。
- **O2**：由我**自动截图核对**（只开一次浏览器，非后台任务）。注意：截图前窗口必须 ≥1200×896，否则 `getBoundingClientRect()` 返回缩放后的值会导致验收误判。
- **O3**：**系统默认字体**，不引用不内嵌。
- 三项均已锁定，具备开工条件，等用户说「开工」。

### 开发完成（index.html 已交付 + 自动化验收通过）

- 交付：`E:\new-journey\index.html`，单文件纯静态，M1–M6 全部达成。
- 验收脚本：`.workbuddy/tools/verify.js`（**CDP 直连系统 Edge**，Node 22 内置 WebSocket，零安装；用 `Emulation.setDeviceMetricsOverride` 把视口钉成 1200×896 使 scale=1 再量坐标）；截图在 `.workbuddy/tools/shots/`。
- **编码期抓到 3 个只有跑起来才暴露的 bug**：
  1. `fitStage()` 的 `Math.min` 没封顶 → 窗口 >1200×896 时会放大画面。改为 `Math.min(w/1200,h/896,1)`。
  2. `#act2` 全屏层 `opacity:0` 也拦截点击 → 第一幕 START 完全点不动。加 `pointer-events:none`。
  3. `#stage` 作为 flex 子项被 shrink，内部坐标系被挤成 1174×803，所有 right/bottom 定位基准错。加 `flex:0 0 auto`。
- 引导手落点从计划的 (940,690) 改为 **(989,548)**：像素级验证 `chat.png` 从局部 y=314 起是**全宽度不透明面板**（画布 y≥714 全被对话框覆盖），原坐标会被完全遮住。
- 最终实测坐标全部命中规格：btn-start 距底 170、btn-go right100/bottom50、suitcase right50/bottom30、chat-text 500×140 @ (540,730)。
- 遗留决策：行李箱按计划的图层顺序（道具 10 < 对话框 30），底部约 150px 被对话框遮住；若要完整露出，把 `#suitcase` 的 z-index 提到 35 即可（一行）。等用户确认。
- 复用要点：**Windows 上做网页视觉验收不必装 Playwright**，用系统 Edge + `--headless=new --remote-debugging-port` + CDP WebSocket 即可截图和点按。
