## 1. 项目概述

一个以「收拾行李出发去旅行」为主题的点击式（Point-and-Click）叙事 Demo。玩家通过点击推进剧情，全程由本地美术素材 + 打字机对话 + 引导手提示驱动，无分支、无失败状态，属于线性叙事体验。

**情节概要**：
主角 Luna 站在车站站台（第一幕）→ 点击 START → 回到房间开始收拾行李，发现新买的行李箱没有任何标记、容易被别人拿错（第二幕）→ 点击行李箱，场景切换到行李箱画面（第三幕）→ Luna 提议贴上自己最喜欢的贴纸，做出「专属行李箱」；玩家从右侧贴纸面板挑选贴纸，逐个贴到左侧行李箱上，贴满 3 个以上后点击 OK（可选择 RESET 全部重贴）→ 达成目标，弹出 Goal Achieved 卡片（第四幕）→ 点击 Continue，画面全黑，Demo 结束。

## 2. 技术约束（硬性要求）

| 项 | 要求 |
|---|---|
| 交付形态 | 单个 `index.html`，纯静态，零依赖、零构建 |
| 运行方式 | 双击打开（`file://`）即可运行，也支持本地 HTTP 服务 |
| 画布尺寸 | **内部坐标严格 1200 × 896**，所有元素按此坐标系绝对定位 |
| 显示适配 | 窗口小于 1200×896 时，**整幅画面等比缩放**以适配窗口（仅显示层缩放，内部坐标与元素相对位置完全不变）；窗口 ≥ 1200×896 时按 1:1 居中，**不放大** |
| 素材引用 | 使用相对路径引用本地 `assets/`、`audio/`，不使用外链、不联网 |
| 字体 | 使用**系统默认字体**，不引用、不内嵌任何网络字体 |
| 后台任务 | **不得在后台生成任何任务/子 Agent**，一次性产出完成 |
| 兼容性 | 现代浏览器（Chrome / Edge），桌面端鼠标点击操作 |
| 资源预加载 | 第一、二幕素材开场前全部预加载（保持秒开）；**第三、四幕素材在第二幕收尾的黑幕转场期间并行预加载**，避免 4.5MB 视频拖慢开场 |

### 2.1 坐标系约定

以画布左上角为原点 `(0, 0)`，x 向右递增，y 向下递增。文档中同时给出「距底部像素」换算，便于对齐。

- 画布：`W = 1200`，`H = 896`
- 水平居中轴：`x = 600`
- 换算公式：`top = 896 - 距底部距离 - 元素高度`

> 该坐标系为**内部逻辑坐标**，与窗口大小、显示缩放无关。窗口缩放只作用于最外层显示，本文档所有像素值均按此坐标系书写。

### 2.2 视频素材播放约定（新增）

| 项 | 要求 |
|---|---|
| 播放方式 | `<video>` 全屏铺满画布，`width:100%; height:100%`，`object-fit: fill`（见 §6.2 说明） |
| 定位 | `left:0; top:0`，与背景图完全重合 |
| 自动播放 | 允许（进入第三幕前玩家已完成多次点击，满足浏览器自动播放策略） |
| 结束处理 | `ended` 事件 → 定格为静态图 `bg-room-suitcase.png`（见 §6.3） |
| 声音 | **默认静音**（`muted`），待确认项 **Q8** |

### 6.6 贴纸玩法机制（核心）

**玩法循环**

> **Q14 已确认：采用「自由落点」方案。** 落点由玩家在行李箱上自由决定，**不在箱身上预设固定落点**。

1. 玩家在右侧贴纸面板**点击任意一张贴纸** → 该贴纸进入「**待放置**」状态：从槽位升起、跟随鼠标光标移动（半透明预览，中心对齐光标），面板中该贴纸转为置灰态
2. 玩家把光标移到左侧**行李箱箱身范围内**点击 → 贴纸**贴在该点击点**并落定
3. 落定后：贴纸计数 +1（待确认 **Q15**：同一张贴纸是否允许重复使用）
4. 当**箱身上的贴纸数 ≥ 3** 时，`btn-ok` 由**置灰禁用**变为**可用**（待确认 **Q16**：「3 个以上」按 ≥3 理解）
5. 点击 `btn-reset` → **清空箱身全部贴纸**，调色板 12 张贴纸全部恢复可用，计数归零，`btn-ok` 回到置灰态
6. 点击 `btn-ok`（仅在可用时）→ 进入第四幕

**⚠️ 「自由落点」导致的交互变化（需知悉）**

原始需求写的是「点击后贴纸到左边的行李箱上贴住」，暗含**一次点击**完成落位。
但**落点既然由玩家自由决定，一次点击就无法确定位置**，因此确认 Q14 后，交互必然变为两步：

> **① 在右侧点击选中贴纸（贴纸跟随光标） → ② 在左侧行李箱上点击确定落点**

这是「自由落点」的必然结果，**不是额外新增的操作步骤**。若日后更想要「一次点击即贴上」的手感，可切回预设落点方案（见 §6.6.1 备选 A）。

**落点判定规则（自由落点必须明确的边界）**

| 场景 | 规则 |
|---|---|
| **有效落点范围** | 点击点（即贴纸**中心**）必须落在**行李箱箱身**内，实测范围 `x 150–536` / `y 246–779`（校准项见 §10.5） |
| 贴纸边缘超出箱身 | **允许** —— 只要中心在箱身内即视为有效；贴纸边缘可自然压出箱体轮廓外，更贴近真实贴纸效果 |
| 点击箱身**以外**区域 | 不落定、不计数；贴纸**飞回原槽位并取消待放置态**（**Q24 已确认**，见 §10.3） |
| 待放置时点击**面板中的另一张**贴纸 | 切换待放置目标：当前贴纸飞回槽位，新贴纸进入待放置态 |
| 待放置时点击 RESET / OK | RESET 正常生效（并取消待放置）；OK 在可用时正常生效 |
| 贴纸之间重叠 | **允许**，后贴的压住先贴的（`z-index` 递增） |
| 光标反馈 | 箱身范围内 `cursor: pointer`（可选：箱身整体描边高亮）；范围外 `cursor: not-allowed` |

**贴纸落定形态**

| 项 | 值 |
|---|---|
| 尺寸 | 素材原尺寸 **142 × 119**（与面板中一致，不再缩小；若目测偏大可整体降到 0.8 倍 ≈ 114 × 95） |
| 旋转 | 落定瞬间随机 **−10° ~ +10°**（每次点击重新随机以增强手工感；回归测试可用固定种子保证可复现） |
| 定位 | 以**点击点为中心**：`left = 点击x − 71`，`top = 点击y − 59.5` |
| 层级 | 落定贴纸 `z-index: 10` 起，按贴上顺序递增 |
| 落定反馈 | 轻微「按下去」弹一下：`scale 1.12 → 1.0`，约 180 ms |

**飞入 / 跟随 / 落定 动画**

| 阶段 | 规范 |
|---|---|
| ① 选中升起 | 点击面板贴纸后，从槽位位置**升起并转为跟随光标**，约 200 ms `ease-out`；略缩至 0.9 并加投影，表示「拿起来了」 |
| ② 跟随 | 贴纸中心贴齐光标，`opacity: .85`；用 `pointermove` + `requestAnimationFrame` 节流更新位置 |
| ③ 落定 | 在箱身内点击 → 由跟随态过渡到落定形态（缩放回 1.0、旋转到随机角度），约 180–250 ms，落点轻微回弹 |
| ④ 取消 | 在箱身外点击 → 贴纸飞回原槽位（约 250 ms），恢复面板可点状态（**Q24 已确认**：必须飞回取消，不保留在手上） |
| 音效 | **选中时**播放一次 `toggle.wav`；**落定时**再播放一次 `toggle.wav` |

**实现要点（自由落点最大的坑：缩放补偿）**

`#stage` 在窗口小于 1200×896 时会被 `transform: scale(s)` 缩放（此时 `s < 1`），鼠标的**客户端坐标不能直接当画布坐标用**，否则窗口一变贴纸就会偏。必须换算：

```
rect  = stage.getBoundingClientRect()
s     = rect.width / 1200
画布x = (e.clientX - rect.left) / s
画布y = (e.clientY - rect.top)  / s
```

- `s` 直接从 `getBoundingClientRect()` 反推即可，无需依赖外部状态变量
- **跟随定位**与**落点命中判定**必须使用**同一套换算后的坐标**，否则会出现「看起来能贴、实际贴不上」
- 跟随层建议加 `will-change: transform` 并用 `translate3d()`，提升为合成层避免每帧重排

#### 8.1.1 幕的显隐门控（硬约束，v2.4 新增）

**要求：任一时刻，画面上只能有「当前幕」一幕整体可见。**

本 Demo 的每一幕都是一个全屏绝对定位层（`#act1` ~ `#act4`），层级靠 `z-index` 排。因此**未激活的幕必须整幕不可见**，而不只是「里面的元素各自透明」—— 后者只要漏掉任何一个常驻可见的元素，它就会连同所在幕的 `z-index` 一起盖住当前幕。

**典型反例（真实发生过）**：第三幕的 `#bg-room-suitcase` 是**常驻可见**的定格图（它不像视频那样自带淡入淡出），若 `#act3` 容器漏写 `opacity: 0`，这张图会从页面载入的第一帧起盖住第一、二幕 —— 玩家看到的是「一亮相就是行李箱的房间、没有开始界面、画面怎么都不动」。而且它因为设了 `pointer-events: none`，点击仍会穿透到下面被遮住的 START 按钮，所以**流程其实走得通，只是全程看不见** —— 这类问题极难由玩家描述、也极难由常规断言发现。

| 幕容器 | 初始态 | 激活方式 |
|---|---|---|
| `#act1` | **可见**（`opacity:1`，开场就要显示） | — |
| `#act2` | `opacity:0` + `pointer-events:none` | 加 `.in` → `opacity:1` |
| `#act3` | `opacity:0` | 加 `.active` → `opacity:1`（激活瞬间 `#blackout` 仍是全黑，可瞬时切换） |
| `#act4` | `opacity:0` | 加 `.active` → `opacity:1`（其子元素各自仍是透明，逐个淡入） |

> **新增一幕时**：`.scene` 容器必须自带 `opacity: 0` + 一个激活类；并**必须**在验收时确认既有幕没有被新幕盖住（见 §12 的对应验收项）。
