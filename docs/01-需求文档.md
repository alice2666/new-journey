## 1. 项目概述

一个以「收拾行李出发去旅行」为主题的点击式（Point-and-Click）叙事 Demo。玩家通过点击推进剧情，全程由本地美术素材 + 打字机对话 + 引导手提示驱动，无分支、无失败状态，属于线性叙事体验。

**情节概要**：
  
主角 Luna 站在车站站台（第一幕）→ 点击 START → 回到房间开始收拾行李，发现新买的行李箱没有任何标记、容易被别人拿错（第二幕）→ 点击行李箱，场景切换到行李箱画面（第三幕）→ Luna 提议贴上自己最喜欢的贴纸，做出「专属行李箱」；玩家从右侧贴纸面板挑选贴纸，逐个贴到左侧行李箱上，贴满 3 个以上后点击 OK（可选择 RESET 全部重贴）→ 达成目标，弹出 Goal Achieved 卡片（第四幕）→ 点击 Continue，画面全黑 → **（v2.12 起这是转场，不再是终点）** 播放飞行视频，抵达一座古城堡（第五幕）→ Luna 落地感叹「飞了 30 多个小时终于到了」，随即提议进屋（两句对话，各点一次 GO）→ 进入城堡室内，画面切到室内场景、出现「纸片」可点击物件，Luna 感叹「一走进来就像穿越回过去」，又注意到地上有纸片（两句对话，各点一次 GO）→ 对话框消失，引导手出现并指向纸片，玩家点击纸片 → **画面黑屏**（**v2.12 起这是转场，衔接第六幕**；Demo 终点后移到第六幕末尾）。

## 2. 技术约束（硬性要求）

| 项     | 要求                                                                                        |
| ----- | ----------------------------------------------------------------------------------------- |
| 交付形态  | 单个 `index.html`，纯静态，零依赖、零构建                                                               |
| 运行方式  | 双击打开（`file://`）即可运行，也支持本地 HTTP 服务                                                         |
| 画布尺寸  | **内部坐标严格 1200 × 896**，所有元素按此坐标系绝对定位                                                       |
| 显示适配  | 窗口小于 1200×896 时，**整幅画面等比缩放**以适配窗口（仅显示层缩放，内部坐标与元素相对位置完全不变）；窗口 ≥ 1200×896 时按 1:1 居中，**不放大** |

#### 3.5.2 素材体积与加载策略（**Q30 已确认：独立加载、不阻塞开场**）

- 该 WAV **未压缩**，5.05 MB —— 比第三幕视频（4.54 MB）还大。按 §2 现行预加载策略，**第一、二幕素材在开场前全部预加载**；把 5.05 MB 的 BGM 塞进开场预加载队列会让**第一、二幕的「秒开」目标被破坏**（这正是当初把视频挪到幕间预加载的原因）。
- **最终决议（Q30）**：**BGM 不并入开场预加载队列**，改为**独立、不阻塞**的加载 ——
  1. `preload()` 的 `Promise.all` **不包含** BGM，开场时序完全不受它影响；
  2. BGM 自己用 `preload="auto"` 独立拉取，**加载失败或超时绝不阻塞开场、不得产生未捕获错误**（沿用现有 `loadAudio()` 的 2.5 s 兜底思路）；
  3. **起播策略**：点击 START 时**已就绪 → 立即起播**；**未就绪 → 等它就绪的瞬间起播**（而不是整场静音）。
- **为什么这条好办**：起播点在「点击 START」之后，而第一幕「画面淡入 → START 淡入 → 等玩家点击」本身就有**数秒操作窗口**可缓冲，实际几乎总是已就绪。
- 需要区分两件事：**BGM「开始播放」的时机**（需求锁定为「点击 START 后」）与 **BGM「何时下载」**（已定为「独立、不阻塞」）。

#### 3.5.3 兼容性注意（`file://` 自动播放）—— **v2.9 起已不构成障碍**

- 素材为**本地 WAV**（非流式），无跨域问题。
- 浏览器会拦截「**无用户手势**的发声播放」，但 **v2.9 的起播点是一次真实的 START 点击**，手势条件在起播那一刻已经满足，因此**无需任何探测、兜底或补播逻辑**。
- 对比：第三幕视频能自动播放，靠的也是「走到那里时玩家已点过多次」；而 v2.8 曾把 BGM 放在第一幕第一帧，那时玩家一次都没点，才需要绕行。**该绕行方案随 v2.9 一并取消。**

#### 3.6.1 `btn-papers.png` 的像素几何（实测）

素材为 **195 × 123** 的透明底 PNG，画面上是「散落的碎纸片」。实测：

| 项            | 实测值                                        |
| ------------ | ------------------------------------------ |
| 画布（图片本身）     | 195 × 123                                  |
| 不透明墨迹包围盒     | `x 0–194` / `y 0–122`（**墨迹填满整张图片，四边无空白边距**）  |
| 透明区域         | 纸片**之间**有少量全透明缝隙（整张图的不透明占比 ≈ 87%）          |
| 是否近似圆形/圆角矩形 | 否 —— 轮廓是**不规则的多片碎纸外接矩形**，外接框就是 195 × 123   |

> **由此引出的 Q36（v2.12 已确认）**：因为墨迹**填满整张图、四边没有留白**，若直接把图片左上角放在需求给定的坐标上，**用户量到的「屏距」是图片外接框的边，不是纸片视觉重心的位置**。而纸片之间还有透明缝隙，所以曾有两种口径：
> - 「距右 290 / 距下 120」指 **图片外接框（195×123）** 还是 **纸片群视觉外轮廓**？

### 6.6 贴纸玩法机制（核心）

**玩法循环**

> **Q14 已确认：采用「自由落点」方案。** 落点由玩家在行李箱上自由决定，**不在箱身上预设固定落点**。

1. 玩家在右侧贴纸面板**点击任意一张贴纸** → 该贴纸进入「**待放置**」状态：从槽位升起、跟随鼠标光标移动（半透明预览，中心对齐光标），面板中该贴纸转为置灰态
2. 玩家把光标移到左侧**行李箱箱身范围内**点击 → 贴纸**贴在该点击点**并落定
3. 落定后：贴纸计数 +1（待确认 **Q15**：同一张贴纸是否允许重复使用）
4. 当**箱身上的贴纸数 ≥ 3** 时，`btn-ok` 由**置灰禁用**变为**可用**（待确认 **Q16**：「3 个以上」按 ≥3 理解）
5. 点击 `btn-reset` → **清空箱身全部贴纸**，调色板 12 张贴纸全部恢复可用，计数归零，`btn-ok` 回到置灰态
6. 点击 `btn-ok`（仅在可用时）→ 进入第四幕

**⚠️ 「自由落点」导致的交互变化（需知悉）**


原始需求写的是「点击后贴纸到左边的行李箱上贴住」，暗含**一次点击**完成落位。
  
但**落点既然由玩家自由决定，一次点击就无法确定位置**，因此确认 Q14 后，交互必然变为两步：

> **① 在右侧点击选中贴纸（贴纸跟随光标） → ② 在左侧行李箱上点击确定落点**

这是「自由落点」的必然结果，**不是额外新增的操作步骤**。若日后更想要「一次点击即贴上」的手感，可切回预设落点方案（见 §6.6.1 备选 A）。

**落点判定规则（自由落点必须明确的边界）**

| 场景                  | 规则                                                                                                                                   |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| **可显示范围（有效落点范围）**   | 行李箱上有一个矩形**可显示范围**（用户给定红框实测换算），画布坐标 **`x 146–540` / `y 259–793`**（宽 394 × 高 534）。判据：**整张贴纸（142 × 119 未旋转外框）必须完整落在这个框内**（**Q25 已确认**） |
| 换算得到的**中心**可落点区间    | 由红框四边各内缩半个贴纸 → **`x 217–469` / `y 318.5–733.5`**；贴纸中心落在该区间内才算有效                                                                      |
| 贴纸任一边超出范围           | **不允许** —— 即使贴纸**中心**仍在框内，只要任一边越出边界即判为「超出范围」→ 不落定、不计数、**飞回原槽位**（Q25；旧版「只判中心、允许压出最多 71 / 59.5px」的规则已作废）                               |
| 点击可显示范围**以外**区域     | 不落定、不计数；贴纸**飞回原槽位并取消待放置态**（**Q24 已确认**，见 §11.3）                                                                                      |
| 待放置时点击**面板中的另一张**贴纸 | 切换待放置目标：当前贴纸飞回槽位，新贴纸进入待放置态                                                                                                           |
| 待放置时点击 RESET / OK   | RESET 正常生效（并取消待放置）；OK 在可用时正常生效                                                                                                       |
| 贴纸之间重叠              | **允许**，后贴的压住先贴的（`z-index` 递增）                                                                                                        |
| 光标反馈                | **整张贴纸能完整落入范围**时 `cursor: pointer`；否则 `cursor: not-allowed`（判定与落点判定同源，不能各写一套）                                                        |

**飞入 / 跟随 / 落定 动画**

| 阶段     | 规范                                                                                    |
| ------ | ------------------------------------------------------------------------------------- |
| ① 选中升起 | 点击面板贴纸后，从槽位位置**升起并转为跟随光标**，约 200 ms `ease-out`；略缩至 0.9 并加投影，表示「拿起来了」                  |

| ③ 落定   | 点击点满足「整张贴纸完整落入可显示范围」→ 由跟随态过渡到落定形态（缩放回 1.0、旋转到随机角度），约 180–250 ms，落点轻微回弹                |
| ④ 取消   | 点击点不满足上述条件（含「中心在框内但贴纸会压出边界」）→ 贴纸飞回原槽位（约 250 ms），恢复面板可点状态（**Q24 / Q25**：必须飞回取消，不保留在手上） |

**实现要点（自由落点最大的坑：缩放补偿）**

`#stage` 在窗口小于 1200×896 时会被 `transform: scale(s)` 缩放（此时 `s < 1`），鼠标的**客户端坐标不能直接当画布坐标用**，否则窗口一变贴纸就会偏。必须换算：

```
rect  = stage.getBoundingClientRect()
s     = rect.width / 1200
画布x = (e.clientX - rect.left) / s
画布y = (e.clientY - rect.top)  / s
```

- `s` 直接从 `getBoundingClientRect()` 反推即可，无需依赖外部状态变量
- **跟随定位**与**落点命中判定**必须使用**同一套换算后的坐标**，否则会出现「看起来能贴、实际贴不上」
- 跟随层建议加 `will-change: transform` 并用 `translate3d()`，提升为合成层避免每帧重排

#### 9.1.1 幕的显隐门控（硬约束，v2.4 新增）

**要求：任一时刻，画面上只能有「当前幕」一幕整体可见。**

本 Demo 的每一幕都是一个全屏绝对定位层（`#act1` ~ `#act6`），层级靠 `z-index` 排。因此**未激活的幕必须整幕不可见**，而不只是「里面的元素各自透明」—— 后者只要漏掉任何一个常驻可见的元素，它就会连同所在幕的 `z-index` 一起盖住当前幕。

**典型反例（真实发生过）**：第三幕的 `#bg-room-suitcase` 是**常驻可见**的定格图（它不像视频那样自带淡入淡出），若 `#act3` 容器漏写 `opacity: 0`，这张图会从页面载入的第一帧起盖住第一、二幕 —— 玩家看到的是「一亮相就是行李箱的房间、没有开始界面、画面怎么都不动」。而且它因为设了 `pointer-events: none`，点击仍会穿透到下面被遮住的 START 按钮，所以**流程其实走得通，只是全程看不见** —— 这类问题极难由玩家描述、也极难由常规断言发现。

| 幕容器     | 初始态                                 | 激活方式                                                   |
| ------- | ----------------------------------- | ------------------------------------------------------ |
| `#act1` | **可见**（`opacity:1`，开场就要显示）          | —                                                      |
| `#act2` | `opacity:0` + `pointer-events:none` | 加 `.in` → `opacity:1`                                  |
| `#act3` | `opacity:0`                         | 加 `.active` → `opacity:1`（激活瞬间 `#blackout` 仍是全黑，可瞬时切换） |
| `#act4` | `opacity:0`                         | 加 `.active` → `opacity:1`（其子元素各自仍是透明，逐个淡入）             |
| **`#act5`（v2.12）** | `opacity:0` + `pointer-events:none` | 加 `.active` → `opacity:1`（激活瞬间 `#blackout` 仍是全黑，可瞬时切换） |
| **`#act6`（v2.12，待开发）** | `opacity:0` + `pointer-events:none` | 加 `.active` → `opacity:1`（激活瞬间 `#blackout` 仍是全黑，可瞬时切换） |

> **新增一幕时**：`.scene` 容器必须自带 `opacity: 0` + 一个激活类；并**必须**在验收时确认既有幕没有被新幕盖住（见 §13 的对应验收项）。
>
> ⚠️ **第五幕的风险点（必须照 §9.1.1 的老教训办）**：`#act5` 里 `bg-inside.png` 与视频都是**全屏常驻可见/可激活**的元素，而 `#act5` 的 z-index(5) **高于全部前四幕**。因此 `#act5` 若漏写 `opacity: 0`，`bg-inside.png` 会**从载入第一帧起盖住整部 Demo**（第一幕的 START 都看不见）—— 这正是 D4 的翻版。**`gate` 用例必须扩到覆盖 `#act5`。**
