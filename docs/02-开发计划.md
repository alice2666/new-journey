## 1. 范围与目标

按需求文档 v2.2 实现**第一幕 ~ 第四幕**完整 Demo，终点为第四幕末尾的全黑静止画面。全程原生 HTML/CSS/JS，零依赖、零构建、零网络请求，双击 `index.html` 即用。

| 幕 | 内容 | 状态 |
|---|---|---|
| 第一幕 | 车站站台：START → 进房间 | ✅ 已实现并通过验收 |

## 2. 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 技术栈 | 原生 HTML + CSS + JavaScript（ES6） | 单文件交付、零依赖、双击即用 |
| 渲染方式 | DOM + CSS `transform` / `opacity` 动画 | 元素少，无需 Canvas，坐标可控 |
| 动画驱动 | CSS `transition` / `@keyframes` 为主，JS 只切类名 | 保证流畅，避免 JS 逐帧 |
| 打字机 | `requestAnimationFrame` + 时间累积 | 比 `setInterval` 稳，且便于中途取消 |
| **视频（新增）** | 原生 `<video>` 元素，`object-fit: fill` 铺满 | 无需解码库；仅 1 段 4.10s 视频 |
| **光标跟随（新增）** | `pointermove` + `requestAnimationFrame` 节流，改 `transform` | 跟随必须逐帧更新；用 transform 走合成层不触发重排 |
| **缩放补偿（新增）** | `getBoundingClientRect()` 反推缩放比 | `#stage` 被 `scale()`，鼠标坐标必须换算成画布坐标 |
| 音频 | `Audio` 对象池（3 实例轮询） | 0.11s 短音可重叠播放，不打断 |
| 字体 | **系统默认字体**，不引用也不内嵌 | 需求禁止联网 |
| 显示缩放 | 最外层 `transform: scale()` 等比适配窗口 | 内部坐标保持 1200×896 不变 |

### 4.1 场景容器与层叠模型（**实现前必读**）

需求文档 §8.1 的 z-index 表是**按「所有元素平铺在 `#stage` 下」**描述的。但现有代码里第一、二幕已经用了**场景 wrapper**（`#act1` / `#act2`），而 wrapper 一旦有 z-index 就形成**层叠上下文**，其子元素的 z-index 只在 wrapper 内部比较。

本版沿用 wrapper 方案（改动最小、且与已有 `#act2` 一致），**wrapper 之间的先后由下表决定，wrapper 内部再按需求 §8.1 的相对层级排**：

| z-index | 容器 | 说明 |
|---|---|---|
| auto | `#act1` | 第一幕（`opacity` 切显隐） |
| 2 | `#act2` | 第二幕（现状） |
| **3** | `#act3` | 第三幕（新增） |
| **4** | `#act4` | 第四幕（新增） |
| 100 | `#blackout` | 纯黑遮罩，**始终在最上**，转场与终点共用 |
| 110 | `#act3-slot` / `#act5-slot` | 预留容器（保持空） |

> ⚠️ **由此推出两条容易踩的结论**：
> 1. 第二幕末尾黑幕要「淡出露出视频」—— 视频在 `#act3`（z=3）里，黑幕在 z=100，**黑幕淡出即可露出视频，不需要调层级**。但 `#blackout` 默认 `pointer-events:none`，淡出后点击会穿透到第三幕 —— 视频播放期间需要**透明但仍拦截点击**，见 §6.18 的 `.guard`。
> 2. 第四幕的 `shadow`（表内 90）/ `goal01`（95）/ `continue`（96）都写在 `#act4` 内部，只需保证组内相对顺序即可，**不必也不该**去和 `#act3` 内部的 30/40 抢层级。

## 6. 核心实现方案

### 6.1 画布与坐标系（含等比缩放）—— 现状不变

`#stage` 固定 `width:1200px; height:896px; position:relative; overflow:hidden`，所有子元素 `position:absolute` + 精确 px，**不使用 flex/auto 布局**。外层 `#viewport` 负责居中与 `scale()`：

```js
function fitStage() {
  // 上限 1：窗口大于 1200x896 时按 1:1 显示，绝不放大
  var s = Math.min(window.innerWidth / STAGE_W, window.innerHeight / STAGE_H, 1);
  stage.style.transform = 'scale(' + s + ')';
}
```

| 窗口情况 | 缩放比 | 效果 |
|---|---|---|
| 窗口 ≥ 1200×896 | `s = 1` | 1:1 原始尺寸居中，**不放大** |
| 窗口 < 1200×896 | `s < 1` | 整幅等比缩小，居中，无滚动条 |

- ⚠️ 截图/断言前必须先把窗口设为 ≥1200×896 使 `s = 1`，否则 `getBoundingClientRect()` 返回缩放后的值，量出来与文档不符。
- ⚠️ **反向影响**：第三幕的**鼠标坐标必须乘/除缩放比**才能得到画布坐标 —— 见 §6.14，这是本版最危险的一处。

### 6.2 分幕函数结构（本版重构）

现有 `main()` 是一条 18 步的 `Promise` 链。第三幕的**玩法循环是事件驱动、非线性**的（玩家可任意顺序点贴纸 / RESET / OK），无法继续用线性链表达。因此拆成三个函数：

```js
runAct1to2()   // 现有 Promise 链，改动仅两处：
               //   ① 末尾不再是终点 —— 黑幕停 500ms 后 resolve
               //   ② 期间并行预加载第三、四幕素材（§6.17）
  .then(runAct3)   // 视频 → 定格 → 第三句 → 面板入场（线性）
                   // 入场完成后交棒给事件驱动的玩法循环
  → 玩法循环内点 OK 时调用 runAct4()

runAct4()      // 蒙黑 → Goal → Continue → 全黑（线性）
```

**状态机（全量命名）**

```
S0_LOADING → S0_TITLE → S1_ROOM → S2_WAIT_GO_1 → S3_SUITCASE → S3_WAIT_GO_2
  → S4_HINT → S5_BLACK(转场 500ms)
  → A1_VIDEO → A2_FRAME → A2_TYPE3 → A3_WAIT_GO_3
  → A4_IN_PANEL → A4_IN_STICKERS → A4_IN_BUTTONS
  → A4_PLAY ★（事件驱动：贴纸 / 箱身 / RESET / OK 四个监听器）
  → G1_MASK → G2_GOAL → G3_WAIT_CONTINUE → G3_END
```

`★ A4_PLAY` 之前的过渡状态由 `enterState(name)` 统一处理「显示/隐藏哪些元素、是否允许点击」。

### 6.3 打字机（参数化写入目标）

现有 `typeText(text, speed)` 硬写 `#chat-text`。第三幕要往 `.chat-text` 打字，需**把写入目标参数化**：

`screen3/chat.png` 与 `screen2/chat.png` **字节完全相同（md5 一致）**，几何与文本区无需重新定位。为避免把坐标抄第二份，把现有 `#chat` / `#chat-frame` / `#chat-text` 的样式**抽成 `.chat` / `.chat-frame` / `.chat-text` 公共类**，两幕各持一个实例（`#chat`（第二幕）与 `#chat3`（第三幕））。

### 6.7 音效

- 预创建 3 个 `Audio('audio/toggle.wav')` 实例轮询，允许重叠
- 触发点（全量）：`btn-start`、`btn-go` ×2、`suitcase`、**`btn-go3`、贴纸选中、贴纸落定、`btn-reset`、`btn-ok`、`continue`**
- 自动播放策略：首个音效触发点就是用户点击 START，天然满足「需用户手势」

### 6.7.1 背景音乐 BGM（v2.7 计划新增，需求 §3.5 / Q27–Q30）

**单实例、独立加载、一次起播一次停止** —— 全片只有 1 个 `Audio` 对象，生命周期由 START 与 Continue 两次点击夹住。

```js
var BGM_SRC = 'audio/music-walker-s.wav';   // 30.0s / PCM 16bit / 44.1kHz / 立体声 / 5.05MB
var bgm = new Audio(BGM_SRC);
bgm.preload = 'auto';      // 独立拉取：不并入 preload() 的 Promise.all（Q30）
bgm.loop = true;           // Q28
bgm.volume = 0.35;         // Q27（点击音效维持 0.85 不变）

// 就绪标志：用于「点击 START 时未就绪 → 等它就绪的瞬间起播」
var bgmReady = false;
bgm.addEventListener('canplaythrough', function () { bgmReady = true; }, { once: true });
bgm.addEventListener('error', function () { /* 静默吞掉：绝不阻塞开场，不报错 */ });
try { bgm.load(); } catch (e) { /* ignore */ }

var bgmWanted = false;     // 玩家已点 START，但音乐可能还没就绪
function startBGM() {
  bgmWanted = true;
  if (!bgmReady) return;                       // 还没下载完 -> 交给 canplaythrough 回调补播
  var p = bgm.play();
  if (p && typeof p.catch === 'function') p.catch(function () {});
}
bgm.addEventListener('canplaythrough', function () { if (bgmWanted) startBGM(); });

function stopBGM() {
  bgmWanted = false;
  try { bgm.pause(); bgm.currentTime = 0; } catch (e) { /* ignore */ }
}
```

**接入点（只有两处，其他地方一律不碰 `bgm`）**

| 位置 | 调用 | 说明 |
|---|---|---|
| 点击 `#btn-start` 的处理里（`playSound()` 之后） | `startBGM()` | 全片**唯一**的音乐起点；这一下点击同时也是用户手势，自动播放策略天然满足 |
| 点击 `#continue` 的处理里（`playSound()` 之后） | `stopBGM()` | 全片**唯一**的停止点，先于 `#blackout` 渐入 |

**注意（易错点）**

1. **不要**在页面加载完 / 第一幕背景淡入时调用 `startBGM()` —— 需求（§3.5.1）明确第一幕点击前**全程静音**。
2. **不要**把 `bgm` 加进 `preload()` 的 `Promise.all` —— 5.05 MB 未压缩 WAV 会把开场拖慢；它的加载必须**独立且不阻塞**（Q30）。
3. **幕间切换不得触碰 `bgm`** —— 不 `pause`、不 `currentTime = 0`、不改 `volume`（Q29：跨幕完全连续）。
4. `stopBGM()` 之后**不要**再有任何起播逻辑，结尾必须静音到底。

### 6.8 视频接入（A1 新增）

```html

```

```css
#act3-video { position:absolute; left:0; top:0; width:1200px; height:896px;
              object-fit: fill;      /* 1112×834 → 1200×896，纵横比仅差 0.45% */
              opacity: 0; transition: opacity .25s ease-out; }
#act3-video.in { opacity: 1; }
```

**转场时序（`S5_BLACK → A1_VIDEO`）**

1. 第二幕末尾 `#blackout` 已 `opacity:1`，**停留 500ms**（期间并行预加载三、四幕素材，§6.17）
2. 视频就位 → `video.currentTime = 0` → `video.play()`（`muted`，见 Q8）
3. 等到**首帧可播**（`canplaythrough` / `playing` 事件）→ `#blackout` 淡出 400ms **露出视频**
4. 用「黑幕淡出」而非硬切，避免视频首帧与第二幕末帧硬跳

**播放期间屏蔽点击**：`#blackout` 淡出后若直接 `pointer-events:none`，点击会穿透到第三幕控件。做法：给 `#blackout` 加一个**透明守卫类**

```css
#blackout.guard { opacity: 0; pointer-events: auto; }   /* 透明但仍拦截点击 */
```

视频播放期间保持 `.guard`，`ended` 后移除。

**结束 → A2**：监听 `ended` → 视频**淡出 250ms**，露出下层的 `#bg-room-suitcase`（静态图**始终存在**于视频下层，这样即使末帧与静态图有细微差异也不会闪黑 —— 见 Q10）。

**降级路径（必须实现）**：若 `play()` 被拦截或 `canplaythrough` 超时（3s 上限），**跳过错帧**：隐藏视频、直接进入 A2 定格 + 对话，不让流程卡死。

### 6.10 贴纸玩法（A4_PLAY，**本版核心与最大风险点**）

#### 6.10.1 交互模型（两步，Q14 已确认）

> **① 点右侧面板贴纸 → 贴纸升起并跟随光标 → ② 点左侧箱身落点 → 贴住**

落点由玩家自由决定，**不在箱身上预设任何固定点位**。这两步是「自由落点」的必然结果，不是额外增加的操作。

#### 6.10.2 缩放补偿（最危险的坑）

`#stage` 带 `transform: scale(s)`，**`e.clientX/Y` 是视口坐标，不能直接当画布坐标**。必须统一换算，且**跟随定位与落点判定必须用同一套换算后的坐标**，否则会出现「看着能贴、实际贴不上」：

```js
function toStage(e) {
  var r = stage.getBoundingClientRect();
  var s = r.width / STAGE_W;                  // 缩放比直接从 rect 反推，无需外部状态
  return { x: (e.clientX - r.left) / s, y: (e.clientY - r.top) / s };
}
```

- 跟随层定位：`#sticker-cursor` 内贴纸 `left = x - 71`、`top = y - 59.5`（**中心对齐光标点**）
- 落点判定与落定定位：用**同一个** `toStage()` 结果
- 跟随层加 `will-change: transform` 并用 `translate3d()` 提升为合成层，避免每帧重排

#### 6.10.3 状态与判定规则

| 项 | 规则 |
|---|---|
| 有效落点 | **整张贴纸**（142×119 未旋转外框）完整落在**可显示范围**红框 `x 146–540` / `y 259–793` 内。实现上先算出中心可落点区间 `x 217–469` / `y 318.5–733.5`，再判 `toStage(e)` 得到的中心是否落入 |
| 贴纸边缘超出范围 | **不允许**（Q25）—— 即使中心仍在框内，只要任一边越界即判无效。旧版「只判中心、允许压出 71/59.5px」已作废 |
| 点击范围外 / 贴纸会压出边界 | **Q24 + Q25**：飞回原槽位、取消待放置、**不计数**（250ms） |
| 待放置时点面板另一张 | 当前贴纸飞回槽位，新贴纸进入待放置态 |
| 待放置时点 RESET | RESET 正常生效并取消待放置 |
| 贴纸重叠 | **允许**，后贴的压住先贴的（z-index 递增） |
| 同一张贴纸重复使用 | **不能**（Q15）：用后置灰；RESET 后恢复 |
| 光标反馈 | 箱身内 `cursor: pointer`；范围外 `cursor: not-allowed` |

#### 6.10.4 落定形态

| 项 | 值 |
|---|---|
| 尺寸 | 素材原尺寸 **142 × 119**（不缩放） |
| 旋转 | 落定瞬间随机 **−10° ~ +10°**（每次重新随机；回归测试用固定种子保证可复现） |
| 定位 | `left = 点击x − 71`，`top = 点击y − 59.5` |
| 层级 | 落定贴纸从 `z-index: 10` 起，按贴上顺序递增 |
| 落定反馈 | `scale 1.12 → 1.0`，约 180ms |

#### 6.10.5 四段动画

| 阶段 | 规范 |
|---|---|
| ① 选中升起 | 点击面板贴纸后由槽位升起并转跟随光标，约 200ms `ease-out`；缩至 0.9 + 投影（表示「拿起来了」） |
| ② 跟随 | 中心贴齐光标，`opacity: .85`；`pointermove` + `rAF` 节流 |
| ③ 落定 | 180–250ms：缩放回 1.0 + 旋转到随机角 + 落点轻微回弹 |
| ④ 飞回取消 | 约 250ms `ease-out` 回到原槽位 |

#### 6.10.6 计数与按钮态

- 落定成功 → 计数 +1
- **计数 ≥ 3**（Q16：按「含 3 个」理解）→ `#btn-ok` 由置灰禁用变可用
- `#btn-ok` 禁用态：`opacity .45 + grayscale(1) + cursor:not-allowed + 不响应点击`
- `#btn-reset` **全程可点**（Q17），点击 → 清空箱身全部贴纸 + 调色板 12 张全部恢复 + 计数归零 + 取消待放置 → `#btn-ok` 回到置灰
- 计数**不显示数字**（无对应素材），`#btn-ok` 的可用态即唯一反馈

### 6.11 第四幕（G1–G3）

| 步 | 动作 | 时长 |
|---|---|---|
| 1 | 点击 `#btn-ok` → 音效 | — |
| 2 | **第三幕 UI 整体淡出**（面板 + 调色板 + 两按钮 + 已落定贴纸） | 300ms |
| 3 | `#shadow` 淡入 → 画面蒙黑（α≈70%，底层隐约可见） | 600ms |
| 4 | `#goal01` 出现（**从上到下快速落下**，Q26） | 380ms |
| 5 | `#continue` **自下而上**滑入（`translateY(120px) → 0`） | 500ms |
| 6 | **点击 `#continue`**（Q20 已确认，不自动延时）→ `#blackout` 渐入 → 静止全黑 | 700ms |

- **第 4 步的「落下」怎么实现**（Q26，需求 §7.2）：
  ```css
  #goal01 {
    transform: translateY(-720px);   /* 起点：下边缘 699-720 = -21，整张在画布上方之外 */
    transition: transform .38s cubic-bezier(.55, 0, .85, .35),  /* 加速下落，近似自由落体 */
                opacity .12s ease-out;                           /* 只用 120ms 点亮，落到一半也看得见 */
  }
  #goal01.in { opacity: 1; transform: translateY(0); }           /* 落点 top = 120 */
  ```
  **为什么是 380 ms（不是 450 ms）**：下落比原来的原地放大更需要「快」才像落体；380 ms 足够看清轨迹又不拖沓。`cubic-bezier(.55, 0, .85, .35)` 是**加速**曲线（前段几乎不动、后段猛地窜下去），端点速度不为零，观感是「砸下来」——若改用 `ease-out` 会变成「滑下来」，与需求不符。
  **`-720px` 是怎么定的**：必须满足「整张卡片在画布上方之外」→ 下边缘 `699 + ty ≤ 0` → `ty ≤ -699`；取 `-720` 留 21 px 余量，避免亚像素舍入让它露一线。
- **第 2 步的 UI 淡出是必要的**（Q21）：`shadow.png` 是 70% 半透明，第三幕 UI 若不淡出会透过蒙黑层若隐若现。
- `#continue` 是第四幕**唯一**可点击元素：`cursor:pointer` + hover 1.05 / active 0.95。
- 结束时预留空容器 `#act5-slot`；不跳转、不加文字、不提供返回按钮。
- 素材备注：`shadow.png` 仅 6.4KB 却是全屏 1200×896 —— 恰好印证它是**纯色均匀半透明层**（实心 `rgba(0,0,0,0.70)`），不是带渐变或纹理的图。

### 6.12 素材预加载策略（分幕，避免开场变慢）

| 阶段 | 加载内容 | 体积 |
|---|---|---|
| 开场（`S0_LOADING`） | 第一、二幕 7 张图 + `toggle.wav` | **3.8 MB** |
| 幕间（`S5_BLACK` 的 500ms 内并行） | 第三、四幕全部：视频 + 定格图 + chat + 面板 + 12 张 + 按钮 + 第四幕 3 张 | **6.4 MB** |
| **全程后台（独立、不参与任何等待）** | **`music-walker-s.wav`（BGM）** | **5.05 MB** |

- 首屏**不加载**三、四幕素材，否则 4.54MB 的视频会把开场拖到数秒黑屏。
- **BGM 也刻意不进开场队列**（Q30）：它是 5.05 MB 未压缩 WAV，比视频还大；把它塞进 `S0_LOADING` 会直接毁掉「秒开」。因此 BGM 走**独立的 `preload="auto"` + `load()`**，加载失败/超时不阻塞任何流程（详见 §6.7.1）。可用的缓冲窗口是「第一幕背景淡入 → START 淡入 → 等玩家点击」这几秒。
- 视频用 `preload="auto"` + `load()` 主动起播准备；静态图用 `new Image()` 预热。
- 预加载是**并行且不阻塞**的：黑幕 500ms 到点就走 A1，`play()` 自身会等待可播；若 3s 内仍未就绪，走 §6.8 的降级路径。
- 全部素材本地读取，Network 面板**零外部请求**。

### 6.13 锁模型（在现有 `busy` 基础上细分）

现有全局 `busy` + 300ms 冷却足以应付线性演出，但**玩法循环是「随时可点」的**，不能再全程上锁。本版分三层：

| 锁 | 作用域 | 说明 |
|---|---|---|
| `busy`（演出锁） | 线性演出 + 打字期间 | 沿用现状；**进入 `A4_PLAY` 后必须保持 `false`**，否则 `waitClick` 会吞掉所有点击 |
| `animLock`（过渡锁） | 仅贴纸交互 | 「落定/飞回」的 250ms 内为 `true`，防止同一张贴纸在飞行中被重复触发；RESET / OK 不受影响 |
| `placing`（待放置标志） | 玩法循环 | 持有当前待放置贴纸对象；`null` 表示手上没有 |
| `#blackout.guard` | 视频播放期间 | 透明但拦截点击（§6.8） |

「点击许可」仍由一个集中函数判定，避免打字中误触。

> **D4 的教训（本计划最重要的一条）**：`getBoundingClientRect` / 类名 / 坐标全绿 **不等于** 画面正确。本页每个幕都是全屏 `position:absolute` 层，任何一层漏了显隐门控就会「画面全错但测试全绿」。新增幕时**必须同时加 `opacity:0` 门控**，并让 `gate` 用例覆盖它。

> **D5 的教训**：**终态几何全绿也不等于动作正确**。「在哪儿」用 `offsetTop` 断言，「怎么去的」必须靠动画期间采样 `computed transform`（§11.5）。凡需求里带「快速 / 缓慢 / 从上到下 / 自下而上」这类过程描述，都要落到采样断言上，否则改回旧动作也不会有人报警。

**关键实现要点（都是踩过才知道的）**

1. 视频会让每个用例多等 4.1s。**除 `full2` 外一律快进**：等黑幕淡出后 `video.currentTime = duration - 0.4` 触发 `ended`。
2. `a3c` 的落点精度断言在 `s = 1` 与 `s = 0.75` 下各跑一遍（`clickCanvas()` 负责把画布坐标换算成视口坐标再派发真实鼠标事件）—— 这正是 R10 的专项目标。
3. **不要用固定 `sleep` 等应用内的锁**：入场类名 `.in` 出现的瞬间动画才开始、`busy` 锁未释放，此时点击会被吞。用 `waitFor(window.__nj.state().busy === false)`。
4. 几何断言统一读**布局坐标**（沿 `offsetParent` 链累加 `offsetLeft/offsetTop`），不读 `getBoundingClientRect()` —— 后者会被 `transform` 动画污染。
5. 解析 `computed transform` 时**必须按矩阵槽位取数，不要用 `replace(/[^0-9.]/g,'')` 剥字符、也不要只取第一个参数**（负号与千位都会被剥坏）。`translateY` 算出来是二维矩阵 `matrix(a,b,c,d,tx,ty)` → **`ty` 是第 6 个值（索引 5）**；若浏览器给的是 `matrix3d(...)` 16 个值 → **`tx = 索引 12`、`ty = 索引 13`**。先把括号内按 `,` 切成数组再按长度分派，两种都能吃。
6. 像素级结论（如「蒙黑层真的半透明」）用页面内 canvas + `getImageData` 断言，比肉眼看截图可靠。
7. **断言「整幕容器」的有效可见性，别只断言里面的元素**（D4 的教训）。本页每一幕都是全屏绝对定位层，未激活幕的元素若没被藏住就会盖住当前幕，而内部元素的类名、opacity、坐标却全部正确。`gate` 用例的做法：沿祖先链累乘 `opacity`，对 `#act1`~`#act4` 逐个断言，保证**任一时刻只有当前幕可见**。注意 `document.elementFromPoint` **测不出这个问题** —— 未激活幕设了 `pointer-events:none`，命中测试会直接跳过它，返回的反而是下面那一层（实测 `hitAtStartBtn` 返回 `btn-start`，看上去「一切正常」）。
8. 新增一幕时，`.scene` 容器必须自带 `opacity:0` + 激活类转可见（`#act1` 除外，它一开始就要显示）。
9. **要断言「某个元素怎么动的」，只能在动画期间采样 `computed transform`，布局坐标量不出来**（§11.5）。

### 11.4 启动兜底与故障自诊断（`.workbuddy/tools/boot-check.js`）

**起因**：本页所有元素默认 `opacity:0`，只有脚本加上 `.in` 才显示 —— 也就是说「**脚本没跑起来 = 全黑 + 点不动 + 零提示**」。这是最难让使用者自行排查的状态：分不清是文件坏了、浏览器太旧，还是打开方式不对。

**兜底机制（内嵌在 `index.html`）**

| 兜底 | 触发条件 | 表现 |
|---|---|---|
| `<noscript>` | JavaScript 被禁用 | 提示需启用 JS |
| 引擎自检 | 缺 `Promise` / `classList` / `requestAnimationFrame` / `Element.closest` | 「浏览器版本过旧」+ 明确列出缺哪几项，然后 `return` 不再往下跑 |
| **素材体检** | 首屏 7 个素材**已加载完但无像素**（404 / 路径不对） | 「素材未能加载」+ 逐个列出失败路径 + 提示需与 `assets/` 同级 |
| 启动看门狗 | 脚本已执行，但 6s 内第一幕仍未渲染 | 「启动超时」+ 当前地址 |
| `main().catch` / 启动 `try` | 任一环节 reject / 初始化同步抛错 | 「运行出错」+ 堆栈 |

> **为什么「素材体检」必须独立于看门狗**：素材 404 时脚本其实**跑得好好的、`.in` 类也加了**，`booted` 已是 `true` —— 只看这个标志会误判成「启动成功」，而用户看到的仍是全黑。所以判据必须是「**图有没有真的解码出像素**」（`complete && naturalWidth === 0`），而不是「类名加没加」。

面板同时打印：UA、打开方式（是否 `file://`）、窗口尺寸、`devicePixelRatio`、缺失能力，并提示按 **F12** 看 Console。

**验证（`boot-check.js`，4 场景 19 项）**

1. 场景 A 正常启动（`1400×1000`）：`#fallback` 保持 `hidden`、第一幕淡入、`booted = true`、零控制台报错。
2. 场景 B 小窗口 `900×672`：缩放比 ≈ `0.75`。
3. 场景 D **`Network.setBlockedURLs` 屏蔽 `assets/screen1/*`** 模拟素材 404：断言报「素材未能加载」、列出失败路径，且**此时 `booted` 确实已是 `true`**（即证明单查 `booted` 会漏判）。
4. 场景 C **`Page.addScriptToEvaluateOnNewDocument` 抹掉 `Promise`** 模拟旧引擎：断言报「浏览器版本过旧」、缺项含 `Promise`，且**第一幕确实未渲染** —— 复现「黑屏」症状。（该注入不可撤销，故本场景固定排在最后。）

### 11.5 「动作」类需求的验收方法（v2.6 新增，Q26 落地）

**背景**：Q26 要求 `goal01.png`「从上到下快速落下」。旧实现是「原地淡入 + 轻微放大」，**用当时全部 23 条 `a4` 断言都发现不了** —— 因为几何断言读的是 `offsetTop`，而 `offsetTop` 只反映**布局位置**，`transform` 属于绘制阶段位移，改 `transform` 时 `offsetTop` 恒定 `120`。换句话说：**元素「在哪儿」和「怎么到那儿的」是两码事，前者的断言对后者完全免疫。**

**做法**：在**点击 OK 之前**就把采样探针装进页面（下落发生在 900 ms 之后，事后再装就来不及了），采集整段动画：

```js
// 在页面内（evaluate 注入）：用 setInterval 而不是 rAF
window.__drop = [];
var el = document.getElementById('goal01');
var t0 = performance.now();
window.__dropTimer = setInterval(function () {
  var m = getComputedStyle(el).transform;   // matrix(1, 0, 0, 1, 0, ty)
  // 括号内按 ',' 切数组：长度 6 -> tx=n[4], ty=n[5]；长度 16 -> tx=n[12], ty=n[13]
  window.__drop.push({ t: performance.now() - t0, tx: tx, ty: ty,
                       op: +getComputedStyle(el).opacity,
                       in: el.classList.contains('in') });
}, 10);
```

用 **`setInterval` 而不是 `requestAnimationFrame`**：headless 下 rAF 会被降频，采样太稀就分不清「380 ms 的连续下落」和「一帧闪现」；而过渡值由文档时间线驱动，即便不重绘也会随样式重算推进，因此 10 ms 定时器能稳定采到 ~38 个点。

**据此断言**（`a4` 用例内）：

| 断言 | 判据 | 守的是什么 |
|---|---|---|
| 起点整张在画布上方之外 | `.in` 后首个采样 `ty + 699 ≤ 0`（实现 `-720`） | 「从**上**落」而非原地浮现 |
| 单调向下 | `.in` 后的 `ty` 序列非递减（容差 0.6 px） | 没有回弹 / 倒放 |
| 只有垂直位移 | 全程 `\|tx\| < 0.5` | 动作是「落」不是「斜飞」；顺带排掉用 `scale` 伪装的旧实现 |
| 有中间态 | `-699 < ty < -5` 的采样 ≥ 3 个 | 排除「瞬间闪现」（闪现一个中间帧都没有） |
| 一边落一边可见 | 中间态里 `opacity` 最小 ≥ 0.5 | 排除「落到位才浮现」（那是淡入，不是落下） |
| 「快速」 | CSS `transition-duration` ≤ 500 ms **且** 实测 `.in` → `ty` 归零 ≤ 700 ms | 两条一起看：只读 CSS 会被「声明了却不生效」骗过，只读实测又会因环境抖动而虚高 |

> **经验**：这次的失败模式是「**旧动作也能通过全部坐标断言**」。凡是需求里出现「快速 / 缓慢 / 从上到下 / 自下而上 / 弹出 / 抖动」这类**描述过程的词**，都必须按本节采样验收，不能只断言终态几何。
>
> **辅助目检（可选）**：用 CDP `Animation.setPlaybackRate(0.12)` 把 CSS 过渡放慢 ~8 倍再截图，就能拿到真正的「下落中途」画面（否则 `Page.captureScreenshot` 自身的耗时会直接吃完整段 380 ms）。注意它**只影响 CSS 过渡、不影响页面里 `sleep()` 驱动的脚本时序**，所以放慢后「卡片还在半空、Continue 已经就位」是正常现象，不要据此判断有 bug。

用户反馈「打开网页后画面不动、第一幕开始界面不见了」。当时排查结论：**文件本身没有问题** —— 241 项断言全绿、零控制台报错、26 个资源路径与磁盘大小写逐一匹配、无 BOM 且 `charset` 正常、git 工作区干净；用 `file://` 直开（不加任何特殊启动参数）第一幕正常显示且可点击。据此判为**打开环境所致**。

### 13.10 交付后修复：场景门控（D4，v2.3）

**用户报障**：打开页面就是「行李箱的房间」，看不到开始界面，画面怎么都不动。

**定位过程（可复用）**

1. **先认画面，别认症状描述。** 把用户截图与素材逐一比对：截图里**没有门**、构图与 `assets/screen3/bg-room-suitcase.png` 一致，而视频《suitcase-move》首帧/末帧都**有门**（构图更远）。→ 画面是**第三幕的定格图**，不是视频帧，说明卡在视频之后。
2. **像素差不能只看数值。** 用户截图与「同一个画面」的像素差有 ~41/765、19% 的像素差 >60 —— 一开始像是「不是同一张图」，实为**截图工具的色彩配置差异**（同一张图与素材比也是 ~41）。**判定同异要看构图特征（有无某个物件、元素归一化位置），不要只看平均像素差**。归一化位置一比就清楚：截图箱体 `x 0.122~0.599`、定格图 `x 0.124~0.600`，差 ≤0.014。
3. **复现要从真实入口走。** 用无头 Edge 打开 `index.html`、**一次都不点击**直接截图 —— 得到的图与用户截图构图完全一致，并读出 `#bg-room-suitcase` 的有效 opacity = **1**、`#act3` 的有效 opacity = **1**（未激活却可见）。**故障复现成立。**
4. `document.elementFromPoint` 在这类问题上**无效**：`#act3` 设了 `pointer-events:none`，命中测试跳过它，返回的反而是底下那层的 `btn-start` —— 看上去「一切正常」，这恰是之前几轮排查都跑偏的原因。

**根因**

```css
/* 错的 */ #act3 { z-index: 3; pointer-events: none; }
/* 对的 */ #act3 { opacity: 0; z-index: 3; pointer-events: none; }
            #act3.active { opacity: 1; pointer-events: auto; }
```

`#act1` / `#act2` 当初都做了 opacity 门控，**新增 `#act3` / `#act4` 时漏了**。而 `#bg-room-suitcase` 与视频不同：它没有自带 `opacity:0`，也没有任何淡入逻辑，是**常驻可见**的 —— 于是它连同所在的 `#act3`(z-index 3) 一直盖在第一、二幕之上。因为 `#act3` 是 `pointer-events:none`，点击仍能穿透到被遮住的 START 按钮，所以**流程其实是能走的**，只是全程看不见前两幕。

**修复**

- `#act3` 补 `opacity:0` + `.active` 转可见（瞬时切换，不做过渡 —— 激活那一刻 `#blackout` 仍是全黑，不会露出下层）。
- 同构的 `#act4` 一并补上。它当前靠三个子元素各自的 `opacity:0` 侥幸没露馅，但属于同一类隐患，**统一门控**后不变式更简单：任一时刻恰好一幕可见。

**回归防线**

新增 `test.js` 用例 **`gate`**（12 项）：沿祖先链累乘 `opacity`，断言「载入时只有第一幕可见 / 第二幕时第三幕仍不可见 / 第三幕激活后整幕可见」。这是本页唯一一条**不测元素、只测整幕可见性**的断言 —— 专门用来堵 D4 这种「内部元素全对、整体盖住了当前幕」的盲区。
